# SEO Audit — myrrys.com

**Date:** 2026-07-27
**Branch:** `blog/ropecon-2026` (commit `791d4cd`)
**Scope:** Static analysis of `dist/` after a clean `pnpm build` — 411 built HTML pages, 410 sitemap entries.
**Method:** Automated extraction of head metadata, heading structure, image alt coverage, JSON-LD types, and the full internal link graph from the built output, plus manual verification of every finding below against source files.

---

## Summary

The metadata *plumbing* on this site is in good shape. Every page except one legacy redirect stub has a title, description, canonical URL, Open Graph tags, Twitter card tags, and Organization + WebSite + BreadcrumbList JSON-LD. There are no missing `alt` attributes anywhere (2,989 images checked), and only 3 broken internal links across 411 pages.

The problem is not plumbing — it's that **84% of the site is metadata-identical**. The 348 SRD pages, which are the site's largest and most linkable content asset, all ship the same `<title>`, the same `<meta description>`, and no `<h1>`. To a search engine these read as one page duplicated 348 times.

Fixing that single template is worth more than everything else in this report combined.

## P0 — Fix these first

### 1. All 348 SRD pages share one title and one description

`src/pages/letl/srd/[...id].astro:31-33` hardcodes the metadata for every page in the collection:

```astro
<Page
  title="L&L - SRD"
  description="Legendoja & Lohikäärmeitä (L&L) Systems Reference Document (SRD) -materiaali. Jaeltu Creative Commons BY-SA 4.0 -lisenssillä."
>
```

Every spell, every equipment table, every rules section — `/letl/srd/loitsut/tulipallo/`, `/letl/srd/varusteet/aseet/`, `/letl/srd/sanasto/` — is submitted to Google with a title of "L&L - SRD" and an identical 118-character description.

**Why this matters.** Duplicate titles and descriptions at this scale are a strong signal that pages are not distinct. Google typically selects one URL as canonical for a duplicate cluster and folds or drops the others from the index. It also means that even for the pages that *do* get indexed, the SERP snippet says nothing about the actual content — nobody searching "tulipallo loitsu" sees a result that looks like an answer.

This is the site's biggest organic-search opportunity. 348 pages of Finnish-language TTRPG rules content is a genuinely valuable long-tail asset that is currently invisible.

**Fix.** Derive the title from each document's own heading, and the description from its opening prose. The SRD collection currently has an empty schema (`src/content.config.ts:59-62`), so there is no frontmatter to read from:

```ts
const lnlsrd = defineCollection({
  loader: glob({ pattern: ["**/*.md"], base: "LnL-SRD" }),
  schema: z.object({}),
});
```

Two options:

- **Extract from content (no submodule changes).** Read the first heading and first paragraph out of the rendered AST or the raw markdown body. Keeps `LnL-SRD` untouched, which matters because it is a shared submodule.
- **Add optional frontmatter.** Extend the schema with `title` and `description` as optional fields and populate them in the submodule over time, falling back to extraction.

Recommend the first — it fixes all 348 pages at once with no content churn. Suggested pattern: `"{Heading} – L&L SRD"`, e.g. `"Tulipallo – L&L SRD"`.

> **Resolved.** Option 2 was tried first (frontmatter added to all 348 files upstream, required in the schema) and reverted: LnL-SRD is a shared document that does not accept generated or site-specific input, metadata included, so 348 hand-maintained descriptions were not sustainable. Option 1 is what shipped — `src/remark/remarkSrdMetadata.ts` derives the title from each document's leading heading and the description from its opening body text, and the route reads them off `remarkPluginFrontmatter`. Do not reopen the frontmatter route.

> Per `CLAUDE.md`, changes to content collection schemas are an **ASK** item — flagging that option 2 needs your sign-off.

### 2. SRD pages have no `<h1>`, and the heading hierarchy is inverted

On `/letl/srd/loitsut/tulipallo/` the rendered heading structure is:

```
<h3 id="tulipallo">Tulipallo</h3>          ← the actual page subject
<h2 class="text-h1">L&L SRD</h2>           ← sidebar TOC nav
<h3>MYRRYS</h3>                            ← footer
<h3>Yhteistyössä</h3>                      ← footer
```

The page's own subject is an `<h3>`; the only `<h2>` is navigation chrome. There is no `<h1>` at all. 347 of the 348 SRD pages have zero `<h1>` (`/letl/srd/readme/` is the exception), and `/letl/srd/olotilat/olotilat/` has two.

The cause is upstream: the source markdown authors each spell as a fragment of a larger document, so `LnL-SRD/loitsut/tulipallo.md` opens with `### Tulipallo`.

This also violates the project's own rule in `CLAUDE.md`: *"Pages must have exactly one H1; components use H2+ with visual utility classes."*

**Fix.** Promote the document's top heading to `<h1>` at render time — a rehype plugin that shifts heading levels for the SRD collection so the shallowest heading becomes `h1` and the rest cascade down. This composes naturally with finding #1: the same extracted heading feeds both the `<title>` and the `<h1>`.

Do not fix this by editing 348 markdown files in the submodule — the levels are correct in the context of the combined document.

> Per `CLAUDE.md`, remark/rehype plugin changes are an **ASK** item.

Site-wide, 333 pages have an `<h1>` count other than exactly one. Beyond the SRD set, the outliers are `/ds/` (2 — design system page, `Disallow`ed in robots.txt, so cosmetic only) and `/letl-suuri-seikkailu/` (0 — a real page that needs one).

## P1 — Address in the next pass

### 3. No `hreflang` annotations

Zero pages emit `hreflang`. `src/layouts/Page.astro` renders `<html lang="fi">` and `src/layouts/EnPage.astro` renders `<html lang="en">`, which is correct, but nothing tells Google that `/` and `/en/` are language variants of the same content rather than competing duplicates.

**Fix.** Add reciprocal `hreflang` links to `BaseHead.astro` for pages that have a counterpart, including `x-default`. This is only worth doing alongside finding #7 — with three English pages there is very little to annotate yet.

### 4. `og:type` is always `website`

`src/components/base/BaseHead.astro:114` hardcodes `<meta property="og:type" content="website" />` for every page.

25 pages already emit correct `Article` JSON-LD, so the structured data and the Open Graph tags currently disagree with each other. Blog posts should be `og:type="article"` with `article:published_time` and `article:author` — the blog schema in `src/content.config.ts` already carries `pubDate` and `author`, so the data is available.

Impact is on social sharing previews and article-level understanding rather than rankings directly. Cheap to fix: add an optional `type` prop to `BaseHead`.

### 5. Blog tag URLs are unslugified

Tag pages are generated directly from raw tag strings, producing URLs like:

```
/blog/tag/l%26l%3A%20suuri%20seikkailu/
/blog/tag/l%26l%2C%20ogl%2C%20errata/
/blog/tag/ropecon%202025/
```

These are percent-encoded spaces, commas, and ampersands. The sitemap and the built directory names agree, so **these pages are not broken** — but the URLs are unreadable, hostile to sharing, and the encoded `&` in particular is fragile across the many contexts where a URL gets pasted.

There is a second, related content problem: comma-joined tags are being treated as single tags. `l&l`, `l&l, ogl`, and `l&l, ogl, errata` are three separate tag pages when they should be posts sharing the tags `l&l`, `ogl`, and `errata`. That splinters the tag taxonomy and creates several near-duplicate thin pages.

**Fix.** Slugify tags when generating paths (lowercase, ASCII-fold, hyphenate), keeping the original string as the display label. Split comma-separated tag values in the source markdown into proper array entries. Add redirects from the current encoded URLs if any have been shared.

> Per `CLAUDE.md`, URL routing pattern changes are an **ASK** item.

### 6. `robots.txt` has no `Sitemap:` directive

Current `public/robots.txt`:

```
User-agent: *
Allow: /
Disallow: /ds
```

The sitemap is correctly generated at `/sitemap-index.xml` and correctly referenced from every page's `<head>`, but crawlers conventionally look for it in `robots.txt`. One line:

```
Sitemap: https://myrrys.com/sitemap-index.xml
```

### 7. The English section is near-empty and partly orphaned

Only 3 pages render with `lang="en"`: `/en/`, `/en/blog/`, and `/ds/` (the design-system page, which is `Disallow`ed and presumably shouldn't be `en` at all).

`/en/` is linked from `TopNavMenu.astro:30`, but **`/en/blog/` has zero inbound internal links** — it is reachable only via the sitemap. And its single blog entry links to `/en/blog/2026-01-sample-post`, which doesn't build (see #8).

In practice the English site is one page. Either commit to it as a real localisation — in which case #3 and #9 matter — or drop it until there's content to justify it. The current state signals an abandoned section to both users and crawlers.

## P2 — Cleanup

### 8. Three broken internal links

| Broken link | Linked from |
|---|---|
| `/letl/srd/loitsut/suojelus_hyvältä_ja_pahalta` | `/letl/srd/loitsut/1_piirin_loitsut/` |
| `/letl/srd/loitsut/veden_luominen_ja_tuhoaminen` | `/letl/srd/loitsut/1_piirin_loitsut/` |
| `/en/blog/2026-01-sample-post` | `/en/blog/` |

The two SRD links are typos in the submodule's spell index. The actual files are:

- `LnL-SRD/loitsut/Suojaus_hyvältä_ja_pahalta.md` — index says *Suojelus*, file says *Suojaus*
- `LnL-SRD/loitsut/Veden_luominen_tai_tuhoaminen.md` — index says *ja*, file says *tai*

Both are one-word fixes in `LnL-SRD/loitsut/1_piirin_loitsut.md` (submodule change).

### 9. Placeholder content is live in production

`src/blog-en/2026-01-sample-post.md` is a template stub that ships to production, appears in `/en/blog/`, and produces a broken link. Delete it or replace it with real content.

### 10. Legacy redirect page uses meta-refresh

`src/pages/legendoja-lohikaarmeita/index.astro` is a hand-written HTML page whose entire body is a meta-refresh:

```html
<meta http-equiv="refresh" content="0; url = https://myrrys.com/letl" />
```

It is the only page on the site with no `lang`, no canonical, and no meta description, and it contains one word of content. Meta refresh is treated as a soft redirect and passes link equity less reliably than a 301.

`astro.config.mjs` already has a `redirects` block handling six other legacy paths. Move this one there and delete the page.

### 11. Thirty descriptions fall outside the useful length range

13 descriptions exceed 160 characters and will be truncated in search results. Worst offenders:

| Page | Length |
|---|---|
| `/letl/letl-kaukasalo/` | 346 |
| `/blog/24-08-02-kultainen-lohikäärme-sorsa/` | 287 |
| `/letl/letl-velhon-torni/` | 289 |
| `/blog/ll-ogl/` | 258 |
| `/blog/flame-tongue/` | 240 |

17 are under 70 characters, mostly the auto-generated tag descriptions (`"Kaikki Kartta -aiheinen sisältö blogissa"`, 40 chars) — low value, but they'd read better with post counts or a topic sentence.

Titles are in better shape: only `/blog/flame-tongue/` exceeds 60 characters (66). The 357 flagged as "too short" are overwhelmingly the duplicate `"L&L - SRD"` string, which finding #1 resolves.

### 12. LCP image preload fires on every page

`BaseHead.astro:69-82` unconditionally preloads two versions of the L&L GM screen splash with `fetchpriority="high"`:

```astro
<link rel="preload" as="image" href="/branding/letl-gm-screen-splash-mobile.webp" media="(max-width: 640px)" fetchpriority="high" />
<link rel="preload" as="image" href="/branding/letl-gm-screen-splash.webp" media="(min-width: 641px)" fetchpriority="high" />
```

Because `BaseHead` is shared by both layouts, all 411 pages high-priority-fetch a hero image that only the homepage displays. On the 348 SRD pages this is a wasted high-priority request competing with the actual LCP element — it makes Core Web Vitals *worse* on 99% of the site while helping one page.

**Fix.** Move the preload behind a prop, defaulting to off, and enable it only on the pages that use the image.

### 13. Redirect targets expose `/index.html` URLs

Generated `dist/_redirects` contains:

```
/LnL-SRD/*    /letl/srd/*/index.html    301
/lnl-srd/*    /letl/srd/*/index.html    301
```

These redirect to a URL ending in `/index.html` rather than the clean canonical path. The canonical tag on the destination points at the clean URL so the damage is contained, but it creates an unnecessary second URL surface for all 348 SRD pages. Change the target to `/letl/srd/:splat`.

Note also that the uppercase `/LnL-SRD/*` source pattern exists for legacy inbound links — that's correct and worth keeping, and it doesn't conflict with the `CLAUDE.md` rule against uppercase in *generated* URLs.

## What's already good

Worth stating plainly, because a lot of this is better than typical:

- **Canonical URLs** on 410 of 411 pages, correctly absolute, derived from `Astro.site`.
- **Structured data** is present and well-formed everywhere: Organization + WebSite + BreadcrumbList on every page, `Article` on 25 blog posts, `Product` (with brand and ISBN) on 6 product pages. No invalid JSON-LD.
- **Image alt coverage is complete** — 2,989 images checked, zero missing `alt` attributes. 1,259 have descriptive text; 1,730 are correctly marked decorative with empty `alt` (mostly the shared thumbnail component).
- **Only 3 broken internal links** out of a large link graph.
- **Sitemap** is generated, complete, and correctly encoded.
- **`lang` attributes** are correct on both layouts.
- **Privacy-first analytics** (Simple Analytics) rather than a heavyweight tracker — good for page weight.
- **Page weight is modest** — the heaviest page is 37 KB of HTML.

## Making it stick

`CLAUDE.md` mandates spec-driven testing, and most of this report is mechanically checkable. This has now been implemented as `tests/seo-corpus.test.ts`, a Vitest suite that parses `dist/` directly and asserts:

- no two pages share a `<title>` or `<meta description>`
- every page has exactly one `<h1>`, and its content heading reaches h1/h2
- every page has a canonical URL and a correct `lang` attribute
- every internal `href` resolves to a built page or a real static asset
- no indexable page is orphaned from internal navigation
- descriptions are 70–160 characters, titles ≤ 60
- JSON-LD parses, declares `@context`, and agrees with `og:type`
- generated URLs contain no reserved or whitespace characters

Run it with `pnpm test:seo` (or `pnpm test:run` for the full Vitest suite). It checks all 411 pages in roughly 250 ms.

**Current baseline: 14 of these fail.** That is intentional — each failure corresponds to a finding above, and they go green as the findings are fixed. The audit is now a build-time guard rather than a snapshot.

Note that nothing currently runs Vitest automatically: `lefthook.yml`'s pre-push hook runs `pnpm build && pnpm test:e2e` only. Until that changes, the corpus suite has to be run by hand.

## Out of scope

This audit covers what is verifiable from the repository and the built output. Three layers were not assessed and need external access or judgment:

- **Index reality** — indexed vs. submitted counts, actual query impressions, and which pages rank. Requires Google Search Console access.
- **Core Web Vitals in the field** — this report reasons about the preload issue analytically; confirming it needs Lighthouse or CrUX data against the deployed site. (`docs/lighthouse_26-02-23.md` exists but predates this branch.)
- **Keyword and content strategy** — whether the titles and descriptions match what Finnish TTRPG players actually search for is editorial work, not static analysis.
